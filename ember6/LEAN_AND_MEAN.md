## The Actual Architecture

```
🔍 WATCHER (always on, lightweight)
    ↓ detects issue
🧠 SWARM (spins up on-demand, parallel agents)
    ↓ outputs solution
🚀 AUTO-DEPLOY (tests, applies, done)
```

**That's it. Three components. No meetings.**

## What Manus Taught Us

From research into Manus and similar systems:

1. **Agents should be ephemeral, not persistent**
   - Spin up when needed
   - Die when done
   - No maintaining "employees"

2. **Parallel > Hierarchical**
   - Multiple agents work simultaneously
   - Vote/consensus on solutions
   - No CEO bottleneck

3. **Context is everything**
   - Agents need full context of the problem
   - Not "departments" with limited scope
   - Each agent sees the whole picture

4. **Fast iteration > Perfect planning**
   - Deploy → Test → Learn → Iterate
   - Don't plan for weeks
   - Ship in minutes

## What We Actually Need RIGHT NOW

**Forget the 15-agent corporate structure.**

Build this instead:

```python
# the_ember_loop.py

while True:
    # WATCH
    issues = watcher.check_everything()
    
    if issues:
        # SOLVE (parallel swarm)
        solution = swarm.solve(issues)  # Multiple agents, one call
        
        # DEPLOY
        if solution.viable:
            deployer.apply(solution)
    
    sleep(60)  # Check every minute
```

**That's the whole system.**

No titles. No hierarchy. Just:
1. Watch
2. Fix
3. Deploy
4. Repeat
